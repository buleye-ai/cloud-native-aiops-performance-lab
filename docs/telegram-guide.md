# Telegram 学习助手使用指南

在公开频道 [FrogsAndDucks](https://t.me/FrogsAndDucks) 中发送以触发词开头
的内容。直接记录会进入思考日志；AI 生成的内容会先发送到机器人私聊，
确认后才进入博客。

## 功能清单

| 触发词 | 输入 | 结果 |
| --- | --- | --- |
| `#思考` | 一段个人思考 | 原样进入[思考日志](/thoughts/) |
| `#面试` | 面试问题或经验 | 进入思考日志并标记“面试” |
| `#总结` | URL 或原始材料 | 审核后发布 Channel 摘要和博客全文 |
| `#写作` | 主题、大纲或原始材料 | 审核后发布 Channel 摘要和博客全文 |
| `#复盘` | 故障现象、时间线和处置记录 | 审核后发布 Channel 摘要和博客全文 |
| `#见解` | 一个观点或需要分析的问题 | 审核后发布 Channel 摘要和博客全文 |
| `#帮助` | 无 | 将本功能清单发送到机器人私聊 |

## 使用示例

```text
#思考
记录不是囤积信息，而是把经历变成可以复用的判断模型。
```

```text
#总结 https://example.com/article
```

```text
#复盘
发布后接口 P99 从 200ms 升至 3s，CPU 使用率只有 40%，回滚后恢复。
```

```text
#见解
运维工程师应该如何利用 AI，而不是被 AI 替代？
```

## 审核与发布

```text
频道指令
→ 主 AI 线路
→ 失败时切换备用线路
→ 机器人私聊发送候选
→ 博客 + Channel / 忽略
→ GitHub 构建部署全文，并向 Channel 发布摘要
```

`#思考` 和 `#面试` 是直接记录；其余 AI 指令必须经过人工审核。同一条
频道消息按 Telegram `message_id` 去重，工作流重试不会重复生成。已批准
但 Channel 发布失败的内容会保留待补发状态，由后续同步自动重试。

## 随时查看功能

在机器人私聊中使用：

```text
/help
```

也可以点击机器人输入框旁的菜单按钮。频道中发送 `#帮助`，机器人会把
同一份清单发送到管理员私聊。

## 每日英语阅读

英语阅读不发到公开技术频道，而是由机器人发送到管理员私聊，避免与博客
通知混在一起：

| 时间（UTC+8） | 内容侧重 |
| --- | --- |
| 08:00 | 日常、通勤、工作沟通与生活安排 |
| 20:30 | 生活、文化、自然、兴趣与通识 |

每篇包含一段短文、5 个词或词组、3 道理解题、隐藏答案和一句可复用表达。
难度按实际推送次数渐进：

1. 第 1—56 篇：A2，约 120—150 词；
2. 第 57—112 篇：A2+，约 150—180 词；
3. 第 113 篇起：B1，约 180—220 词。

同一天、同一时段只会发送一次，即使 GitHub Actions 重试也不会重复推送。
